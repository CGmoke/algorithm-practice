# [2126. 摧毁小行星](https://leetcode.cn/problems/destroying-asteroids/)

###### 难度：1335  标签：贪心   数组  排序

给你一个整数 `mass` ，它表示一颗行星的初始质量。再给你一个整数数组 `asteroids` ，其中 `asteroids[i]` 是第 `i` 颗小行星的质量。

你可以按 **任意顺序** 重新安排小行星的顺序，然后让行星跟它们发生碰撞。如果行星碰撞时的质量 **大于等于** 小行星的质量，那么小行星被 **摧毁** ，并且行星会 **获得** 这颗小行星的质量。否则，行星将被摧毁。

如果所有小行星 **都** 能被摧毁，请返回 `true` ，否则返回 `false` 。



**示例 1：**

```
输入：mass = 10, asteroids = [3,9,19,5,21]
输出：true
解释：一种安排小行星的方式为 [9,19,5,3,21] ：
- 行星与质量为 9 的小行星碰撞。新的行星质量为：10 + 9 = 19
- 行星与质量为 19 的小行星碰撞。新的行星质量为：19 + 19 = 38
- 行星与质量为 5 的小行星碰撞。新的行星质量为：38 + 5 = 43
- 行星与质量为 3 的小行星碰撞。新的行星质量为：43 + 3 = 46
- 行星与质量为 21 的小行星碰撞。新的行星质量为：46 + 21 = 67
所有小行星都被摧毁。
```

**示例 2：**

```
输入：mass = 5, asteroids = [4,9,23,4]
输出：false
解释：
行星无论如何没法获得足够质量去摧毁质量为 23 的小行星。
行星把别的小行星摧毁后，质量为 5 + 4 + 9 + 4 = 22 。
它比 23 小，所以无法摧毁最后一颗小行星。
```



```python
class Solution:
    def asteroidsDestroyed(self, mass: int, asteroids: List[int]) -> bool:
        asteroids.sort()
        for i in asteroids:
            if mass>=i:
                mass+=i
            else:
                return False
        return True
```

## 核心思路

- 行星的质量 `mass` 初始给定，每摧毁一颗质量 `a` 的小行星，质量会增加 `a`。
- 要判断能否摧毁所有小行星。
- **策略**：将所有小行星按质量从小到大排序，然后依次尝试摧毁。
  若当前质量 `mass >= a`，就摧毁它并增加质量；若遇到无法摧毁的（`mass < a`），则不可能成功，直接返回 `False`。
- 若能遍历完所有小行星，则返回 `True`。

------

## 为什么贪心是正确的？

贪心选择性质：**在任意一步，摧毁当前最小的可摧毁小行星总是最优的**。

证明（交换论证）：
假设存在一种可行的摧毁顺序不是按质量非降序进行。那么必然存在某个时刻，先摧毁了一颗质量较大的小行星 `x`，而后摧毁了一颗更小的 `y`（`y < x`）。

- 既然能摧毁 `x`，说明当时质量 `m >= x`，从而 `m >= y` 也成立。
- 若交换这两步，先摧毁 `y`，质量变为 `m + y`，再摧毁 `x` 时质量更充足（`m + y >= m >= x`），依然可行。
  因此，任何可行顺序都可以在不改变可行性的前提下调整为从小到大的顺序。
  所以按升序排列后贪心模拟是正确的。

------

## 复杂度分析

- **时间复杂度**：O(nlog⁡n)*O*(*n*log*n*)，主要来自排序。
- **空间复杂度**：O(1)*O*(1)（不计排序所需栈空间，或者排序可能用 O(n) 额外空间，但通常可忽略）。

------

## 算法流程

1. 对小行星数组升序排序。
2. 遍历排序后的每个小行星质量 `i`：
   - 如果当前质量 `mass >= i`，则 `mass += i`；
   - 否则返回 `False`。
3. 遍历完成返回 `True`。
