给你一个整数数组 `cards` ，其中 `cards[i]` 表示第 `i` 张卡牌的 **值** 。如果两张卡牌的值相同，则认为这一对卡牌 **匹配** 。

返回你必须拿起的最小连续卡牌数，以使在拿起的卡牌中有一对匹配的卡牌。如果无法得到一对匹配的卡牌，返回 `-1` 。

**示例 1：**

**输入**：cards = [3,4,2,3,4,7]
**输出**：4
**解释**：拿起卡牌 [3,4,2,3] 将会包含一对值为 3 的匹配卡牌。注意，拿起 [4,2,3,4] 也是最优方案。

**示例 2：**

**输入：cards = [1,0,5,3]
输出：-1
解释：无法找出含一对匹配卡牌的一组连续卡牌。

**提示：**

- `1 <= cards.length <= 105`
- `0 <= cards[i] <= 106`


```C++
class Solution {
public:
int minimumCardPickup(vector<int>& cards) {
std::unordered_map<int,int> lastIdx;
int n = cards.size();
int res = INT_MAX;
for(int i=0;i<n;i++){
auto it = lastIdx.find(cards[i]);
if (it != lastIdx.end() ){
res = min(res,i+1-it->second);
}

lastIdx[cards[i]] = i;
}
return res==INT_MAX ? -1 : res;

}

};
```

## 算法思想：哈希表记录每个值"最近一次出现"的下标

### 1. 核心思路

题目要求的是一段**连续**卡牌，其中有一对值相同。若同一个值 v 出现在下标 `last` 和 `i`（`last < i`），那么把 `[last, i]` 整段拿起来就一定含匹配对，长度为 `i - last + 1`；再长、再短的其它包含这一对的区间都不会比它更优。

于是问题等价于：**枚举所有"值相同"的下标对，取 `i - last + 1` 的最小值**。

用哈希表 `lastIdx[value] = 该值最近一次出现的下标`，从左到右扫一遍：

1. 遇到 `cards[i]`，先查 `lastIdx` 里有没有它；
2. 有 → 得到一个候选答案 `i - last + 1`（代码里写成 `i + 1 - it->second`），更新 `res`；
3. 然后把 `lastIdx[cards[i]] = i`，为后面的元素准备"最新的上一次出现位置"。

### 2. 为什么只记最近一次就够

设某个值 v 依次出现在 `p₁ < p₂ < … < p_k`。对固定的右端点 `p_b`，左端点越靠右长度越短，所以只有 `p_{b-1}` 有机会成为最优；其余更早的出现只会给出更长的区间。

遍历时哈希表里存的恰好是**上一次**出现位置，当前 `i` 是**最新**一次出现，正是需要的那一对；一旦把 `lastIdx[v]` 更新成 `i`，旧位置就永远不可能再给出更短区间，可以安全丢弃。所以不需要存全部下标，也不需要排序或分组。

### 3. 正确性

- **res 一定是一个合法答案**：每次更新 `res` 时，区间 `[last, i]` 的两端同值，是真实存在的一对匹配卡牌，长度为 `i - last + 1`，所以 `res ≥ 最优解`。
- **最优解一定会被枚举到**：设最优区间为 `[l, r]`（`cards[l] == cards[r]` 且长度最短）。若 `l` 和 `r` 之间还有同值元素 `m`，则 `[m, r]` 或 `[l, m]` 更短，与最优性矛盾，故 `l` 是 `r` 之前该值的**最近一次**出现。遍历到 `r` 时 `lastIdx` 中存的正是 `l`，于是 `res ≤ 最优解`。
- 两者结合 `res == 最优解`。

### 4. 写法细节与易错点

- **必须"先查后更新"**。若先执行 `lastIdx[cards[i]] = i` 再计算差值，差值恒为 1（自己减自己），答案永远是 1。
- **查询用 `find` / `count`，不要用 `operator[]`**。`lastIdx[x]` 在 key 不存在时会**插入**默认值 `0`，从而把"从未出现"误判成"上一次出现在下标 0"，示例 2 会因此返回错误结果。
- **无解时返回 -1**：用 `INT_MAX` 作为哨兵，遍历结束仍是 `INT_MAX` 说明数组中没有重复值。
- **可用数组代替哈希表**：值域 `cards[i] ≤ 10⁶`，直接开一个 `vector<int>(10⁶ + 1, -1)`（约 4 MB），下标即卡牌值，常数更小、没有哈希冲突与扩容开销。哈希表的好处是不依赖值域，值域很大时更通用。
- `unordered_map` 单次操作是**期望** O(1)，最坏情况（大量冲突）会退化；写成 `reserve(n * 2)` 可减少 rehash。

### 5. 复杂度分析

- 时间复杂度：O(*n*)，每个元素做一次查找 + 一次写入，均为期望 O(1)。
- 空间复杂度：O(min(*n*, 值域))，哈希表最多保存 *n* 个不同值；用数组法则为 O(值域)。

### 6. 和滑动窗口的区别

本题的"最短"特性让窗口法很别扭：窗口右端每遇到一个已出现的值，左端就得收缩到上一个同值位置之后，本质仍是在用"最近出现位置"。用计数维护 `次数 == 2` 的滑窗也能做（缩到该值只剩 1 次为止），同样是 O(*n*)，但要维护计数和收缩循环，代码更啰嗦。

**一句话总结**：求"最短区间内出现重复元素"，就是求**相同值相邻两次出现的最小下标差**，一颗记录"最近位置"的哈希表一次遍历即可。
